# SKALog 디자인 실행 프롬프트 (Pencil / pen.dev)

작업 대상: `design/prototype.pen`
근거 문서: [`docs/ui-ux-spec.md`](../docs/ui-ux-spec.md)

## 사용법

1. **§0 고정 컨텍스트**를 먼저 한 번 붙여넣는다. (세션이 끊기면 다시 붙여넣는다)
2. **§1 → §6**을 순서대로 하나씩 실행한다. **한 번에 두 단계를 시키지 않는다.**
3. 각 단계 끝의 `완료 확인`을 눈으로 통과시킨 뒤 다음으로 넘어간다.
4. 결과가 어긋나면 다음 단계로 가지 말고 **그 단계에서 고친다.** 토큰·컴포넌트 오류는 뒤로 갈수록 복구 비용이 배로 늘어난다.

# §0. 고정 컨텍스트 (맨 처음 1회)

```
당신은 SKALog의 UI 디자이너다. 지금부터 design/prototype.pen 에 디자인을 만든다.
작업 전에 get_editor_state(include_schema: true) 와 get_guidelines 로 스키마와 규칙을 먼저 로드하라.

## 제품
SKALog — SKALA 교육생용 학습 기록장.
반별 23주 강의 일정표를 축으로, 강의자료와 내 기록(과제·노트)을 한 곳에서 관리한다.
한 문장: "설정 없이 바로 쓰는 학습 기록장."

## 이 디자인이 이기려는 대상
노션이다. 기능으로는 절대 못 이긴다. 이길 수 있는 유일한 축은 마찰 제거다.
따라서 모든 화면은 아래 정량 기준을 만족해야 한다. 이것은 취향이 아니라 합격 기준이다.

  - 텍스트 기록 1건 등록: 3클릭 · 30초 이내
  - 파일 첨부 기록 1건 등록: 5클릭 이내
  - 지난 자료 찾기: 2클릭 이내
  - 초기 설정: 0단계
  - 분류(폴더·태그·일정 선택) 결정: 0회
  - 모바일에서 한 손으로 등록 가능
  - 빈 화면: 없음

## 절대 규칙 (위반하면 그 화면은 폐기다)
1. 등록 폼에 "어느 일정에 저장할지" 고르는 필드를 만들지 마라.
   대신 "W03 · Java/Spring 기초 에 저장됩니다" 같은 고정 확인 라벨을 둔다.
2. 등록은 항상 인라인 폼이다. 등록을 위해 다른 화면으로 이동시키지 마라.
3. 빈 상태에 "없습니다" 한 줄만 두지 마라. 반드시 (대체 정보 + 다음 행동 버튼)을 함께 둔다.
4. 모바일에서 주요 액션은 화면 하단 40% 안에 둔다. 엄지가 닿아야 한다.
5. 모바일을 먼저 만든다. 데스크톱은 그것을 넓힌 것이다. 반대로 하지 마라.

## 절대 그리지 말 것
온보딩 투어 · 알림 배지 · 검색 바 · 태그 입력 · 캘린더 그리드 뷰 · 통계 차트 ·
프로필 편집 · 댓글 · 좋아요 · 공유 버튼 · 드래그 정렬 · 리치텍스트 툴바 ·
다크모드 토글 · 아이콘 일러스트 장식 · 그림자를 이용한 카드 부양
(요청하지 않은 요소를 "완성도를 위해" 추가하지 마라. 추가는 마찰이다.)

## 시각 원칙
- 계층은 그림자가 아니라 1px 경계선으로 만든다. (예외: 바텀시트/팝오버만 그림자)
- 색의 90%는 중립색이다. 포인트 컬러는 "누를 수 있는 것"과 "오늘"에만 쓴다.
- 아이콘은 장식으로 쓰지 않는다. 의미가 있을 때만 쓴다(↓ 다운로드, ↗ 새 탭, 📎 첨부).

## 더미 데이터 (모든 화면에서 이 값을 그대로 쓴다. 로렘입숨 금지)
사용자: 탁연우 / 판교 1반
오늘: 2026년 7월 30일 목요일 · W03 (3/23주차)

오늘 자료: "Spring DI 개요.pdf" (PDF · 2.1MB) / "실습 코드 저장소" (링크 · 슬랙 원본)

        · 목 7/30 Java/Spring 기초(자료2) ← 오늘 · 금 7/31 DB 설계 모델링(자료0)
내 최근 기록: [노트] DI 3가지 주입 방식 정리 (W03 · 어제 · 첨부1)
             [과제] Git 실습 과제 제출 (W02 · 3일 전)

# §1. 디자인 토큰

> 여기서 손대면 뒤에서 전부 다시 해야 한다. **가장 신중하게 검수할 단계다.**

# §2. 공용 컴포넌트 6종

> InlineComposer가 이 서비스의 심장이다. 나머지 5개보다 여기에 시간을 더 쓴다.

```
2단계: 공용 컴포넌트를 만든다. 아직 화면(페이지)은 조립하지 마라.
"Components" 섹션을 만들고 그 안에 배치하라. 빈 캔버스에 띄우지 마라.
모든 색·간격·폰트는 1단계 변수를 참조하라. raw 값 사용 금지.

[1] Card
  구조: header(제목 heading + 우측 보조 액션 label) / divider 1px border / body 슬롯
  스타일: bg-surface, border 1px, radius card, padding 16
  variant: default / placeholder(점선 border-accent, 배경 없음, 내용 text-faint)

[2] ListItem  — 일정행·자료행·기록행이 전부 이 하나다
  구조: [좌 리드 44px] [중앙: 제목 body 1줄 말줄임 + 메타 meta] [우: 배지 + chevron]
  최소 높이 56, 좌우 padding 16, 탭 영역은 행 전체
  variant: schedule / material / record
  state:   default / hover(bg-subtle) / today(bg today-soft + 좌측 3px today-vivid 바)

[3] Badge
  week      "W03"        중립. 현재 주차만 today 색
  today     "오늘"        text today / bg today-soft
  type      "과제"/"노트"  과제=assignment, 노트=note (각자 bg 사용)
  count     "📎 2"        중립. 0이면 렌더 안 함
  hasRecord 점 6px        primary. 옆에 보이지 않는 라벨 "기록 있음"
  status    "대기"/"승인"/"반려"  중립 / success / danger
  높이 20, radius pill, padding 좌우 8, badge 타이포

[4] InlineComposer  ★ 가장 중요
  variant를 4개 다 만든다.
  (a) collapsed : 높이 44, 점선 border-accent, radius control,
                  텍스트 "+ 이 강의에 기록 남기기" (text-muted), 전체가 탭 타깃
  (b) expanded  : 위에서부터 순서대로
        · 확인 라벨 "W03 · Java/Spring 기초 에 저장됩니다" (meta, text-muted)
          ※ 이건 라벨이지 선택 필드가 아니다. 드롭다운처럼 보이게 만들지 마라.
        · 세그먼트 ( 노트 | 과제 ) — '노트'가 기본 선택(bg primary-soft, 경계 primary-tint)
        · 입력 "제목"  단일행, 필수, 포커스 상태로 그린다
        · 입력 "내용 (선택)"  3행 높이
        · 텍스트 버튼 2개: "📎 파일"  "🔗 링크"   ← 작게. 필수 필드처럼 보이면 안 된다
        · 우하단 [취소](고스트) [저장](primary 채움)
  (c) saving    : 저장 버튼 비활성 + 좌측 소형 스피너. 레이아웃 이동 없음
  (d) with-file : 파일 칩 "Spring실습.pdf 1.2MB ✕" 1개가 붙은 상태

[5] EmptyState
  구조: 안내문(body) / 구분선 / 대체 정보(meta) / 액션 버튼(primary)
  아이콘·일러스트를 넣지 마라. 장식 대신 정보를 둔다.
  예시 내용: "아직 기록이 없습니다" / "다음 강의는 8/3(월) W04 · AI 활용 개발" /
             [오늘 강의에 기록 남기기]

[6] Sheet (모바일 바텀시트)
  상단 radius 16, 그림자 0 8px 24px rgba(0,0,0,.12), 상단 핸들바 36x4
  메뉴 항목: 수정 / 파일 추가 / 삭제(danger)

만든 뒤 스크린샷을 찍고 아래를 스스로 점검한 다음, 문제가 있으면 고쳐라(최대 3회):
- 텍스트나 입력 필드가 컨테이너 폭을 채우는가 (hug이 아니라 fill인가)
- 좌우 padding이 시각적으로 대칭인가
- 탭 가능한 요소가 전부 44px 이상인가
- 1단계 변수를 안 쓰고 하드코딩한 값이 있는가
```

**완료 확인** — InlineComposer expanded에서 "일정을 고르는 UI"가 보이면 실패다. 다시 시킨다.

  맨 아래 "더 보기" 버튼 (무한 스크롤 아님)

[화면 5] 로그인
  중앙 정렬. "SKALog"(display) / "설정 없이 바로 쓰는 학습 기록장"(body, text-muted)
  버튼 1개: "슬랙으로 시작하기" (primary 채움, 폭 100%, 높이 52)
  하단 안내(meta): "SKALA 슬랙 워크스페이스 구성원만 이용할 수 있습니다"
  같은 섹션에 [반 선택] 화면도 1개 더:
    "어느 반이신가요?" / 드롭다운 1개 "판교 1반 ▾" / [시작하기] /
    "나중에 설정에서 바꿀 수 있습니다"(meta)
  ※ 입력 필드를 1개보다 많이 만들지 마라.

전부 만든 뒤 스크린샷으로 점검하고 고쳐라(최대 3회):
- 가로 스크롤이 생기는 곳이 있는가 (375에서 잘리면 실패)
- '오늘'을 나타내는 요소가 화면당 정확히 필요한 곳에만 있는가
- 하단 탭바에 콘텐츠가 가려지는가 (본문 하단 여백 72 확보)
- 우하단 96x96 영역이 비어 있는가 (전역 슬롯 예약 자리 — 아무것도 그리지 마라)
```

**완료 확인** — 홈에서 "기록 남기기"까지 몇 번 눌러야 하는지 세어본다. **2번**이어야 한다.

# §4. 상태 화면 + 인터랙션 연결

> 여기까지 하면 사용자 테스트가 가능하다. **최소 검증 단위다.**

```
4단계: 상태 변형과 클릭 흐름을 만든다.

[A] 상태 변형 화면 (Mobile 섹션에 이어서)
  1. 홈 / 로딩      : 카드 3개 골격 + 회색 바 스켈레톤.
                      최종 화면과 높이가 같아야 한다(레이아웃 이동 금지). 스피너 금지.
  2. 홈 / 오늘 강의 없음 : 카드1 제목이 "다음 강의"로 바뀌고
                      "8/3(월) W04 · AI 활용 개발 · 이애본" 표시.
                      컴포저는 "최근 강의(7/30 Java/Spring)에 기록 남기기"로 유지.
                      ※ 강의 없는 날에도 기록 경로가 살아 있어야 한다.
  3. 일정 상세 / 컴포저 펼침 : InlineComposer(expanded) + 하단에 키보드 영역(291px)을
                      회색 블록으로 표시하고, 저장 버튼이 키보드 바로 위에 sticky로 붙은 모습
  4. 일정 상세 / 저장 직후 : 목록 맨 위에 새 항목이 primary-soft 배경으로 하이라이트된 상태
                      + 하단 토스트 "기록했습니다   실행 취소"
  5. 일정 상세 / 자료 없음 : "자료가 아직 올라오지 않았습니다 ·
                      보통 수업 후 3시간 내 반영됩니다" (수집 주기를 알려 불안을 없앤다)
  6. 내 기록 / 빈 상태  : EmptyState 사용
  7. 일정표 / 아코디언 열림 : 화 7/28 행 아래에 자료 2개가 들여쓰기로 펼쳐진 모습
                      ※ 이 아코디언이 '자료 찾기 2클릭'을 만드는 장치다. 반드시 만든다.
  8. 카드 단위 에러   : 카드2만 "불러오지 못했습니다 [다시 시도]",
                      카드1·3은 정상 표시 (전체 화면 에러로 덮지 마라)

[B] 프로토타입 연결 — 아래 3개 흐름만 클릭 가능하게 이으면 된다
  흐름1 (등록): 홈 → 컴포저 탭 → 펼침 → 저장 탭 → 저장 직후 화면
  흐름2 (자료찾기): 일정표 → 📎2 배지 탭 → 아코디언 열림
  흐름3 (포트폴리오): 내 기록 → 항목 탭 → 일정 상세

  전환은 200ms ease-out. 화면 전체 슬라이드 전환을 남발하지 마라.
```

**완료 확인** — 흐름1을 직접 클릭해 본다. 중간에 화면이 통째로 바뀌면 원칙 위반이다(제자리 입력).

## 부록: 프롬프트를 고칠 때의 원칙

- **"예쁘게 해줘"라고 하지 마라.** 에이전트는 그 말을 "요소를 더 추가하라"로 해석한다. 대신 "카드2의 좌우 padding이 비대칭이다. 16으로 맞춰라"처럼 대상과 값을 준다.
- **한 번에 한 가지만 고친다.** 지적을 5개 묶어 보내면 3개만 반영되고 2개는 조용히 무시된다.
- **결과가 마음에 안 들면 다시 시키기 전에 이 문서를 먼저 고친다.** 같은 프롬프트로 다른 결과를 기대하는 게 가장 흔한 낭비다.
- 스펙이 바뀌면 [`docs/ui-ux-spec.md`](../docs/ui-ux-spec.md)를 먼저 고치고, 그 다음 이 프롬프트를 맞춘다. 순서를 뒤집지 않는다.
