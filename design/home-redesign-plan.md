# 홈 화면 재설계 계획 (2026-08-03)

요구사항 6건 + "카드 일변도 탈피 / 인터랙티브 UI" 를 반영한 `design/prototype.pen` · `frontend/` 수정 계획.
**아직 아무것도 구현하지 않았다.** 이 문서를 승인한 뒤 착수한다.

## 0. 먼저 짚을 것 — 이 변경이 건드리는 기존 원칙

요구사항 자체는 명확한데, 지금 문서에 박아둔 규칙 몇 개와 정면으로 부딪힌다. 나중에 "왜 규칙을 어겼냐"가 되지 않게 **먼저 개정할 조항을 명시**한다.

| 기존 조항 | 충돌 내용 | 처리 |
| --- | --- | --- |
| §5.1 홈 = "오늘 할 일이 여기 다 있다가 3초 안에 읽혀야 한다" | 공지·식단·외부링크·쇼케이스가 들어오면 3초 목표가 흔들린다 | **목표를 유지하되 위계로 푼다** — 오늘 강의는 스크롤 없이 첫 화면, 나머지는 그 아래. §1 참조 |
| §2.2 "탭이 3개뿐이라 하단 바가 과하지 않다" | 쇼케이스 페이지가 늘면 탭 4개가 될 수 있다 | **결정 필요** (§6-Q1). 기본 제안은 탭 3개 유지 |
| §15 "그리지 않을 것" — 검색 바·통계 차트·온보딩 투어 등 | 이번 추가분은 이 목록에 없다. 다만 원칙 6("기능 추가를 성과로 삼지 않는다")은 여전히 적용 | 각 블록마다 **"이게 클릭 수를 줄이는가"** 를 §1 표에 적어 근거를 남긴다 |
| §3.3 "그림자 없음. 1px border 로 계층 표현" | "카드 말고 다른 요소", "동적 UI" 를 그림자로 풀고 싶어진다 | **그림자는 계속 금지.** hover 는 색·보더·미세 이동으로만 (§3) |
| §3.1.1 색 금지 규칙 (핑크=오늘 전용, 민트=진행바 전용, 그라데이션 1곳) | 블록이 늘면 색을 쓰고 싶어진다 | **그대로 유지.** 새 블록은 전부 중립색 + primary 로만 |
| 원칙 4 "오늘을 기준으로 동작한다" | 탭 이름을 '오늘'→'홈' 으로 바꾸면 시그널이 약해지나? | 원칙 4의 판정 기준은 **"진입 시 스크롤 위치가 오늘인가"** 이지 라벨이 아니다. 홈이 오늘 외 정보도 담게 되었으므로 '홈' 이 정확한 이름이다 → §2.2 표만 개정 |

## 1. 새 홈 정보 위계

핵심 판단: **홈을 "대시보드"로 만들지 않는다.** 카드 6장을 나열하면 지금보다 더 단조로워질 뿐이다.
대신 **위에서 아래로 성격이 다른 4개 층**을 쌓고, 층마다 다른 UI 형태를 쓴다.

```
[1층] 오늘          — 히어로 존 (카드 아님, 배경 워시)     ← 첫 화면에서 끝
[2층] 바로가기      — 가로 스크롤 타일 레일 (카드 아님)
[3층] 소식          — 공지 목록 + 주간 식단 스트립 (카드 아님)
[4층] 학습 맥락     — 이번 주 일정 + 내 최근 기록 (기존 카드 유지)
```

| 층 | 블록 | 형태 | "클릭 수를 줄이는가?" |
| --- | --- | --- | --- |
| 1 | 인사 + 날짜 + 진행도 | 히어로 (플랫 텍스트 + 진행 트랙) | — (맥락 제공) |
| 1 | 오늘 강의 + 자료 + 컴포저 | 히어로 내부 강조 존 | 기존과 동일 (기록 2클릭 유지) |
| 2 | SKALA HUB · 출결 · 회의실 예약 · 쇼케이스 | **가로 타일 레일** | ✅ 북마크/검색 대신 1클릭 |
| 3 | 슬랙 공지 | **목록 + 헤어라인** (카드 아님) | ✅ 슬랙 앱 전환 없이 확인 |
| 3 | 주간 식단표 | **5열 요일 스트립** | ✅ 별도 공지 스크롤 불필요 |
| 4 | 이번 주 일정 | 카드 (기존) | 기존 |
| 4 | 내 최근 기록 | 저널 스파인 (기존 M4 형태 재사용) | 기존 |

### 데스크톱 1440

- 히어로는 본문 폭(880) 전체를 쓰는 **가로 밴드**. 좌: 인사/날짜/진행, 우: 오늘 강의 요약.

- 이번 주 / 내 최근 기록은 기존 2열 그리드 유지.

## 2. 요구사항별 반영안

### 요구 1 — 탭 이름 '오늘' → '홈'

건드릴 곳:
- `.pen` : `tnWL6`(TabBar 마스터) 의 `nhDHA` 라벨, `ckNFx`(Sidebar) 의 `LLAbT` 라벨. 마스터만 고치면 인스턴스 전파됨.
- `frontend` : `Shell.tsx` 의 `TABS[0].label`, `NAV_GROUPS[0].items[0].label`
- `docs/ui-ux-spec.md` §2.2 표 (`오늘 / 일정표 / 내 기록` → `홈 / 일정표 / 내 기록`)

### 요구 2·3·4 — 공지 / 식단 / "모든 정보를 홈에서"

- **공지**: 카드가 아니라 목록. 각 행 = 제목(body) + 메타(`#공지 · 10분 전`). 행 전체가 탭 타깃(≥56px), hover 시 `bg-subtle`.
  최대 3건 + `더보기 ›`. **전체 목록 페이지는 만들지 않는다** — 슬랙 원본으로 보낸다(§4 데이터 참조).
- **식단**: 5열(월~금) 스트립. 오늘 열만 `today-soft` 배경 + `today` 텍스트. 열을 누르면 그날 중·석식이 아코디언으로 펼쳐진다(일정표 자료 아코디언과 같은 패턴 재사용 — 새 패턴 아님).
- "모든 정보" 는 **무제한 확장이 아니라 위 4층 구조 안에서만** 늘린다. 층이 5개가 되면 홈이 아니라 다른 화면이 필요하다는 신호로 본다.

### 요구 5 — 외부 서비스 바로가기

가로 타일 레일. 타일 1개 = 아이콘 + 라벨 + `↗`.

| 타일 | 링크 | 비고 |
| --- | --- | --- |
| SKALA HUB | 실제 URL **필요** | |
| 출결 관리 | 실제 URL **필요** | |
| 회의실 예약 | 실제 URL **필요** | |
| 쇼케이스 | 내부 `/showcase` | 요구 6 |

- 외부는 `↗`(새 탭), 내부는 `›`. §3.1.1 "링크는 색 대신 아이콘으로 구분" 규칙 그대로.
- 타일 배경은 중립(`bg-surface` + 1px border). **바이올렛 면적을 만들지 않는다**(§3.1.1).

### 요구 6 — 타 교육생 서비스 아카이브

- 신규 라우트 **`/showcase`**, 신규 `.pen` 화면 **M8(모바일) / D5(데스크톱)**.
- 목록 항목: 서비스명 / 한 줄 소개 / 만든 반·이름 / 링크 `↗`.
- 형태: 카드 그리드 대신 **2열 타일**(데스크톱) · **세로 목록**(모바일).
- 필터는 넣지 않는다(검색 바 금지 §15, 항목 수가 적음). 정렬만 최신순 고정.

### 요구 7 — 카드 탈피 + 인터랙티브

**형태 다양화** (전부 기존 토큰만 사용, 새 색 없음)

| 요소 | 어디에 | 카드와 뭐가 다른가 |
| --- | --- | --- |
| 히어로 존 | 1층 | 테두리 없음. 배경만 아주 옅은 워시 |
| 가로 타일 레일 | 2층 | 스크롤 + 스냅. 세로 나열이 아님 |
| 라벨 + 헤어라인 목록 | 공지 | 박스가 없음 (일정 상세 섹션과 같은 방식) |
| 5열 스트립 | 식단 | 표에 가까운 격자 |
| 저널 스파인 | 내 최근 기록 | 점 + 세로선 (M4 에서 이미 쓰는 형태 재사용) |

**hover / 인터랙션** — 그림자 금지 유지. 전부 150ms ease-out (기존 모션 토큰).

| 대상 | Default | Hover / Active |
| --- | --- | --- |
| 바로가기 타일 | `border-line` | `border-primary-tint` + 라벨 `text-primary` + `↗` 2px 오른쪽·위로 이동 |
| 공지 행 | 투명 | `bg-subtle` |
| 식단 열 | 투명 | `bg-subtle` (오늘 열은 `today-soft` 유지) |
| 쇼케이스 타일 | `border-line` | `border-primary-tint` + 제목 `text-primary` |
| 진행 트랙 | — | `ⓘ` hover 시 일수 툴팁 (이미 있는 패턴) |

> `.pen` 은 정적 캔버스라 hover 가 없다. **Default / Hover 를 별도 프레임 쌍**으로 `01 · Components` 에 그려 톤만 확정하고,
> 실제 전환은 프론트에서 CSS transition 으로 구현한다.

## 4. `frontend` 작업 계획

### 4-1. 데이터 (전부 mock, 백엔드 없음)

  id: number

  channel: string        // '#공지'

  url: string            // 슬랙 원본

  date: string           // 'YYYY-MM-DD'
  lunch: string
  dinner: string
}

  id: number
  label: string
  url: string
  external: boolean
  icon: string           // lucide 아이콘 이름

  id: number
  name: string
  summary: string
