# SKALog

반별 강의 일정표를 축으로 강의자료·내 산출물·내 노트를 한 곳에서 관리하는 SKALA 교육생용 학습 홈.

## 구조

```
skalog/
├── backend/     Spring Boot 4.1 (Java 21, Gradle) — API + 정적 서빙
├── frontend/    React 19 + TypeScript + Vite + Tailwind v4
└── docker-compose.yml   로컬 PostgreSQL
```

백엔드 패키지는 계층이 아니라 도메인 단위로 나눈다. 기능이 늘어날 때
폴더 하나만 추가되도록 하기 위해서다.

```
com.skalog
├── common/config   설정 (SPA 폴백 등)
├── health          연결 확인용 엔드포인트
├── user            User, ClassGroup, Role
├── schedule        Schedule
├── material        Material (승인 상태 포함)
├── submission      Submission (과제/노트)
└── admin           승인함 (3단계에서 채움)
```

수집 배치와 API 서버는 서로를 호출하지 않는다. 둘의 유일한 접점은
`material` 테이블이며, `status` 가 계약이다.
`PENDING` 으로 들어오면 승인함에 뜨고, `APPROVED` 가 되면 일정 상세에 뜬다.

## 슬랙 자료 수집

Events API(실시간 웹훅) 대신 **폴링**을 쓴다. 서버가 10분마다 등록된 채널을
`conversations.history` 로 조회해 새 파일·링크를 승인함(`PENDING`)에 쌓는다.

실시간성이 필요 없는 개인 학습 기록장이라 웹훅의 구현·운영 부담(서명 검증,
URL 핸드셰이크, 로컬 개발용 ngrok 터널링)을 감수할 이유가 없다고 판단했다.
Render 슬립으로 폴링이 멈춰도, 스프링 스케줄러가 서버 기동 즉시 첫 실행을
돌리므로 누군가 접속해 서버가 깨는 순간 밀린 자료가 한 번에 수집된다.
그래도 아무도 오래 접속하지 않는 경우를 대비해 승인함에 수동 "지금 수집"
버튼을 둔다.

일정 매칭은 메시지 날짜와 반 일정 날짜의 단순 일치만 본다(추정 없음).
비교와 결정 근거 전체는 [`docs/slack-collector-decision.md`](docs/slack-collector-decision.md) 참고.

## 슬랙 공지 요약

공지 채널도 같은 10분 폴링에 편승한다. 새 메시지마다 Gemini(`gemini-3.5-flash-lite`,
무료 티어)를 한 번 불러 **한 줄 요약**을 받아 `notice` 테이블에 저장하고, 홈은 저장된
값만 읽는다. 공지 볼륨이 하루 수십 건이라 무료 한도로 충분하고, sLLM을 직접 띄우는
운영 부담을 질 이유가 없다고 봤다. 호출은 4초 간격(분당 15회 한도), 실행당 30회 상한,
실패는 1시간 뒤 재시도.

프롬프트는 실제 채널 메시지 15건 + 재게시 시나리오 9건으로 검증했고, 규칙 한 줄 한 줄이
그때 난 문제(상대 날짜 "오늘까지", 층 누락, 링크 오판 등)에 대응한다 — 고치기 전에 같은
세트로 재검증할 것. 잡담·실습 명령어·기사 공유는 모델이 `PASS` 로 거르고, 최근 공지 목록을
함께 넘겨 같은 내용의 재게시는 `DUP:id` 로 잡는다. 모델이 "지난주 급식표"처럼 같은 종류의
다른 공지를 중복으로 오판하지 못하도록 날짜·차수·층 토큰이 하나도 안 겹치면 코드가 거부한다.

노출 범위는 **반 → 층 → 모두** 세 단계다. 반 채널 공지는 그 반만, 층 채널 공지는 그 층의
반들만, 캠퍼스·전체 공지는 모두가 본다. 같은 공지가 여러 채널에 올라오면 독자가 겹치는
만큼만 하나로 합치고, 더 넓은 채널에 올라오면 기존 공지의 범위를 넓힌다(1반에 먼저 올린
공지가 나중에 층 공지로 오면 다른 반도 보게 된다). 반↔채널 매핑은 `class_group.slack_channel_id`,
층·캠퍼스 채널은 `application.yml` 의 `slack.notice-channels` 에 둔다. 비공개 채널이라
봇을 초대받은 채널만 채워진다.

## 시작하기

사전 준비: JDK 21, Node 20 이상, Docker

```bash
cp .env.example .env      # 값 채우기
docker compose up -d      # PostgreSQL 기동
```

백엔드 (터미널 1):

```bash
cd backend
./gradlew bootRun
```

프론트엔드 (터미널 2):

```bash
cd frontend
npm install
npm run dev
```

`http://localhost:5173` 접속. 홈 화면에 `서버 ok · DB up` 이 보이면
브라우저 → 서버 → DB 경로가 뚫린 것이다. 이것이 0단계의 완료 조건이다.

개발 중에는 Vite dev server(5173)와 백엔드(8080)를 따로 띄운다.
`/api` 요청은 Vite proxy 가 백엔드로 넘긴다.

## 배포 빌드

프론트를 빌드해 백엔드 jar 안에 넣어 단일 서버로 배포한다.

```bash
cd backend
./gradlew bootJar -Pfrontend
java -jar build/libs/skalog-0.0.1-SNAPSHOT.jar
```

## 스키마 변경

Flyway 로만 변경한다. `ddl-auto` 는 `validate` 이므로
엔티티와 테이블이 어긋나면 애플리케이션이 뜨지 않는다.

새 마이그레이션은 `backend/src/main/resources/db/migration/` 에
`V2__설명.sql` 형식으로 추가한다. 이미 적용된 파일은 수정하지 않는다.

## 개발 순서

| 단계 | 내용 | 완료 기준 |
| --- | --- | --- |
| 0 | 스캐폴딩 + 빈 껍데기 배포 | `.env` 가 추적되지 않고, 홈에서 DB up 확인 |
| 1 | 일정 적재 → 일정표·상세 | W01~W23 이 실제 데이터로 보임 |
| 2 | 내 기록 등록·조회 | **모바일에서 3클릭 30초 이내 등록** |
| 3 | 강의자료 표시 (수동 입력) | 일정 상세에 자료가 붙음 |
| 4 | 슬랙 수집기 + 승인함 | 슬랙 업로드가 후보로 뜨고 승인 시 노출 |
| 5 | 홈(오늘) 카드 그리드 | 카드 추가가 삽입만으로 가능 |
| 6 | 슬랙 OIDC + 권한 검사 | 다른 워크스페이스 계정이 거부됨 |
| 7 | 반응형 마무리 → 파일럿 | 375px·1440px 동일 기능, 새로고침 404 없음 |

## 아직 정하지 않은 것

기획서 13.1 중 아래는 해당 단계 전까지 결정한다.

- 반별 일정이 다른가 / 일정 데이터를 어떻게 확보하나 → 1단계 전
- 과제 파일 업로드를 v1 에 넣는가 → 2단계 전
- 강의자료를 서버에 복사해도 되는가 → 4단계 전
